# Codex Runner Admin

A local admin dashboard for inspecting execution logs generated by
[`codex-cli-runner`](https://github.com/anggadb/codex-cli-runner).

The dashboard summarizes runner health and lets you search, filter, and inspect
individual task runs, including their timing, approval activity, shell commands,
output, and errors.

## Features

- Overview metrics for total runs, success rate, average duration, and commands
- Search by task, project, or task ID
- Filter successful and failed runs
- Detailed execution timing and approval information
- Command and output inspection
- Copy filtered records as JSON
- Responsive desktop and mobile layouts
- Automatic log synchronization before development and production builds

## Requirements

- Node.js 22.13 or newer
- A local `codex-cli-runner` installation that produces JSON log files

## Log source

By default, logs are read from:

```text
C:\Users\Angga Bachtiar\Documents\Personal Projects\codex-cli-runner\logs
```

To use another directory, set `CODEX_LOG_DIR` before running a sync, development
server, or build:

```powershell
$env:CODEX_LOG_DIR = "D:\path\to\logs"
npm run dev
```

Each `.json` file in the source directory is collected into `public/logs.json`.
Malformed files are skipped with a warning.

## Getting started

```bash
npm install
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

## Commands

| Command | Description |
| --- | --- |
| `npm run sync:logs` | Refresh `public/logs.json` from the configured source directory |
| `npm run dev` | Sync logs and start the local development server |
| `npm run build` | Sync logs and create a production build |
| `npm run start` | Start the production server |
| `npm run lint` | Run ESLint |

## Project structure

```text
app/
  layout.tsx       Page metadata and root layout
  page.tsx         Dashboard UI and interactions
  globals.css      Dashboard styling and responsive layout
public/
  logs.json        Generated browser-readable log data
scripts/
  sync-logs.mjs    Log collection script
```

## Data safety

Runner logs can contain task prompts, command lines, filesystem paths, output,
and errors. Treat `public/logs.json` as sensitive data. Review it before sharing
or deploying this dashboard, and avoid making the site public unless the logs
have been sanitized.
